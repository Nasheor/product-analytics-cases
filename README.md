# product-analytics-cases

Three self-contained product-analytics case studies on public data, each with the SQL, an executed
notebook, reproducible numbers in `results/` and a one-page memo with a recommendation:

1. **Funnel and cohort retention** on the Olist marketplace (`cases/01_funnel_retention/`). The order
   funnel is tight (96.4 % of orders complete the chain) and the finding is retention: only 2.9 % of
   customers order again within six months, while late deliveries (6.8 % of orders) cost 2.0 review
   points. Recommendation: fix the delivery promise before funding loyalty.
2. **Experiment read-out** on the Upworthy Research Archive (`cases/02_experiment_readout/`). A headline
   test chosen by a rule written before the outcomes were seen: the variant lost (-8.3 %, p = 0.064), a
   five-look O'Brien-Fleming rule would have stopped it at look 3, and across 4,862 tests naive peeking
   gives 50.6 % false positives against 14.2 % with the boundary (17.9 % against 4.9 % on two-arm tests).
   Winners shrink from a 39.6 % lift on the half that picked them to 21.5 % on the other half.
3. **Metric-definition review** on Olist (`cases/03_metric_definition_review/`). Six monthly metrics under
   three plausible SQL definitions each: repeat rate differs by up to 101.8 % between two definitions
   a team could both believe, delivered revenue by 43.4 % in the Black Friday month. A spec sheet
   recommends one definition and an owner per metric, all computed from one order-grain table.

The case folders are independent: open one, read its `README.md`, run its `analysis.py`.

## How to run

```
python -m venv .venv
.venv\Scripts\pip install -e .[dev]
.venv\Scripts\python -m product_analytics_cases download
.venv\Scripts\python -m pytest
.venv\Scripts\python -m product_analytics_cases smoke
```

`download` fetches the Olist files from a public Hugging Face mirror and the Upworthy files from their
OSF links, verifies the published sha256 values and writes row counts to `results/data_sources.json`.
It refuses to run for a dataset that has no row in `LICENCE_CHECK.md`. `smoke` runs the three analyses,
syncs and executes the notebooks on a kernel registered inside the venv, and rewrites `results/` in
about three minutes. No key is needed and nothing is paid for. `costcap.py` is the workspace template
and is unused here.

## Method

DuckDB reads the CSV files directly and every number comes from a named query under `cases/*/sql/` or
a named function in the case's `analysis.py`. Case 2 adds a small statistics module
(`src/product_analytics_cases/sequential.py`): Wilson and Newcombe intervals, the pooled z-test, the
minimum detectable effect, O'Brien-Fleming-type boundaries from the Lan-DeMets spending function by
numerical integration, a mixture sequential probability ratio test, and a seeded reconstruction of an
impression stream from per-arm totals. The null re-labelling simulation draws 1,000 streams per test
with a fixed seed. Notebooks are paired `.py` and `.ipynb` files through jupytext and show the results,
run two queries live and display the figures.

## Limits

The Upworthy archive holds totals per arm, not the order of impressions, so the sequential stopping
points are one seeded plausible path. No test appears in both archive files, so the winner's curse is
measured on a seeded half-split of each test. The archive has no guardrail metric. Olist is one
marketplace over two years, the 2016 months are partial, and the divergence percentages in case 3 are
specific to its data. Correlations (lateness and review score) are not causal claims.
